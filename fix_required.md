# FixItNow live audit

Audit date: 2026-11-09 (Asia/Dhaka). Scope: `REQUIREMENTS.md` and all 85 existing `TASKS.md` entries, with live browser and API coverage for the principal journeys. The checklist records prior implementation completion. This audit found regressions and gaps, so it does not certify full conformance.

## Environment and test data

- Started the frontend with `npm run dev` at `http://localhost:3000` and the backend with `npm run dev` at `http://localhost:8001`. The backend used the configured **main database**. The unused temporary database was stopped. No audit records were written to it.
- Used Chrome with independent customer, technician, admin, and guest sessions. Registered a new customer and technician through the UI. Provisioned the admin with the existing seed command because public admin registration is rejected.
- Mutations were scoped to the audit fixtures `audit-mw9iwov8` and `audit-mw9iv0ia`. The earlier run created an additional audit admin and technician before its customer step was retried. Audit records are retained in the main database. Credentials are omitted. Stripe used test mode throughout.
- Applied local app and API URLs to the running processes. No environment files, migrations, application source, or pre-existing user records were edited for this audit.

| F04 | Medium | **Booking badge colors do not match the documented status mapping.** Both customer and technician booking tables use the same secondary variant for REQUESTED, ACCEPTED, and COMPLETED, the same primary variant for PAID and IN_PROGRESS, and the same destructive variant for DECLINED and CANCELLED. | F09 | Medium | **Completed bookings continue to offer “Review” after submission.** Source inspection shows the dashboard gates the action only on COMPLETED. ## Validation and limits

- Passed frontend lint and TypeScript checks, backend build and TypeScript checks, and all four backend regression tests under `node --import tsx --test tests/*.mjs`. Plain Node could not load the backend test suite's extensionless generated Prisma imports. The TSX loader resolved them.
- The live marketplace had fewer than ten listed technician links during the screenshot pass. A real second technician page was unavailable. The nine-per-page data contract is covered by the backend tests, but the built frontend pagination regression suite stopped at its navbar assertion.
- Direct delivery from a configured Stripe endpoint into the local development process was not exercised. The audit used an authenticated Stripe session lookup and signed local replay. No live funds or connected-account payouts were tested.
- The audit did not inject simultaneous booking races, force Stripe disputes, or create unrelated marketplace records to cover every production data permutation. The default build failure and failed browser regressions remain open.
