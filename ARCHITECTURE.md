# FixItNow architecture

Audited 2026-11-07 and reconciled with implementation on 2026-11-08. The frontend is Next.js 16.4.5 App Router with React 19.3, Axios, Zod 4.6, and the installed shadcn `base-mira` preset. It uses root `app/`, `components/`, `lib/`, `hooks/`, and `validations/` directories; there is no `src/`. Public pages fetch from Express through `lib/public-api.ts` and a server-only `API_BASE_URL`. Interactive role pages use same-origin `app/api/` route handlers. The reference project's direct component and filename conventions are recorded in `REFERENCE_STYLE.md`.

Auth route handlers store backend access and refresh tokens in HTTP-only, SameSite cookies. `lib/session-request.ts` forwards the access token to Express and refreshes when needed. `proxy.ts` redirects anonymous dashboard traffic in Next.js 16, while Express checks the current database user, blocked status, role and ownership on every protected endpoint. The browser never receives the refresh token through JavaScript. Login/register forms and every other frontend form use a schema in root `validations/`; field errors, disabled pending actions and confirmed Sonner feedback are provided in the UI.

The sibling backend is Express 5.2 and Prisma 7.10. `src/app.ts` mounts public and role-restricted routes. Responses use `src/utils/sendResponse.ts`; `src/middlewares/globalErrorHandler.ts` shapes errors. `prisma/models/booking.prisma` stores the selected slot, immutable booking price and status. Booking creation claims a future available slot in a transaction and rejects a concurrent second claim. Technician actions enforce ownership and status transitions. Local-only backend commits `45f1e7e` and `aef1ecc` added owner technician profile/service/availability operations and admin category edits needed by the frontend. These changes have not been pushed or deployed.

Stripe is the only payment provider used by the frontend. Existing Express checkout creates a Session for a customer-owned accepted booking using the stored price. Its raw-body webhook verifies Stripe signatures before updating payment and booking records transactionally. Local-only backend commit `8940ead` sends Checkout returns to the frontend success/cancel pages. The success page reads customer-owned payment state through Express; the redirect itself never marks a payment paid. Real test Checkout, Stripe CLI signed delivery, duplicate event replay, expiration, invalid signature, and persisted state are documented in `STRIPE_INTEGRATION.md`.

Local public, customer, technician and admin flows are verified against the configured Prisma Postgres and Stripe test account. Local Chrome checks cover loading, empty/error states, forms, role access, payment returns and narrow layouts. The deployed backend currently returns 200 for public categories and authenticated admin reads, but 404 for the new owner technician profile route because it predates the local backend changes. The user explicitly deferred all deployment work on 2026-11-08. Hosted frontend behavior and the hosted webhook signing-secret match remain unverified; development progress stays below 100% until that later release work is completed.
