# Frontend to Express API map

Source audit: 2026-11-07. These paths are confirmed from `../FixItNow-backend-server/src/app.ts` and its `src/modules/*/*.route.ts` files. Public category, service, technician list, and technician detail GETs were also tested against the deployed API URL in the backend README on 2026-11-07 and returned HTTP 200 with the documented `data` shapes. Protected and mutation routes remain source-confirmed only. Routes return `{ success, statusCode, message, data }` through `src/utils/sendResponse.ts`; errors return `{ success: false, message, errorDetails }`. Auth middleware accepts an `accessToken` cookie or Bearer token and checks the current database user and role.

| Frontend feature | Actual route and authorization | Request / relevant response | Source |
|---|---|---|---|
| Register/login/session | `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me` (auth), `POST /api/auth/refresh-token` | Register `{name,email,password,role}` (`CUSTOMER`/`TECHNICIAN`); login `{email,password}` returns access and refresh tokens; refresh `{refreshToken}` returns access token; `me` returns identity/role | `auth/auth.routes.ts`, `auth/auth.validation.ts`, `auth/auth.controller.ts` |
| Public categories | `GET /api/categories` | Category list | `category/category.route.ts` |
| Public services | `GET /api/services` | Optional `categoryId`, `location`, `minPrice`, `maxPrice`, `minRating`; no text search parameter | `service/service.route.ts`, `service/service.validation.ts` |
| Public technicians | `GET /api/technicians`, `GET /api/technicians/:id` | List optionally filters by `categoryId`, `location`, `minRating`; detail requires UUID | `technician/technician.route.ts`, `technician/technician.validation.ts` |
| Technician profile | `PUT /api/technician/profile` (technician) | `{bio?,skills,experienceYears?,location,profilePhoto?}`; no role-specific GET currently | `technician/technician.route.ts`, `technician/technician.validation.ts` |
| Technician service | `POST /api/technician/services` (technician) | `{title,description,price,durationMinutes,categoryId}`; price is a positive decimal string | `service/service.route.ts`, `service/service.validation.ts` |
| Technician availability | `PUT /api/technician/availability` (technician) | `{slots:[{startAt,endAt}]}` ISO datetimes with offsets; no GET currently | `availability/availability.route.ts`, `availability/availability.validation.ts` |
| Customer booking | `POST /api/bookings`, `GET /api/bookings`, `GET /api/bookings/:id`, `PATCH /api/bookings/:id/cancel` (customer) | Create `{serviceId,availabilitySlotId}`; server chooses price and time, claims a future slot; customer reads only own bookings | `booking/booking.route.ts`, `booking/booking.validation.ts`, `booking/booking.service.ts` |
| Technician booking | `GET /api/technician/bookings`, `PATCH /api/technician/bookings/:id` (technician) | Update `{status}` among `ACCEPTED`, `DECLINED`, `IN_PROGRESS`, `COMPLETED`; service checks ownership and transitions | `booking/booking.route.ts`, `booking/booking.validation.ts` |
| Stripe Checkout/payment reads | `POST /api/payments/create`, `GET /api/payments`, `GET /api/payments/:id` (customer) | Create `{bookingId,provider?:"STRIPE"}` returns `{paymentId,checkoutUrl}`; accepted own booking only; reads are customer-owned | `payment/payment.route.ts`, `payment/payment.validation.ts`, `payment/payment.service.ts` |
| Stripe webhook and returns | `POST /api/payments/webhook`, `GET /api/payments/return/success`, `GET /api/payments/return/cancel` | Webhook raw body and signed event; current return pages send plain text, so frontend `/payment/*` pages are not yet in the Checkout redirect path | `payment/providers/stripe/stripe.route.ts`, `stripe.webhook.ts`, `stripe.controller.ts` |
| Review | `POST /api/reviews` (customer) | `{bookingId,rating,comment?}`; rating integer 1–5 | `review/review.route.ts`, `review/review.validation.ts` |
| Admin users/bookings | `GET /api/admin/users`, `PATCH /api/admin/users/:id`, `GET /api/admin/bookings` (admin) | Status update `{activeStatus:"ACTIVE"|"BLOCKED"}`; no dedicated KPI endpoint | `admin/admin.route.ts`, `admin/admin.validation.ts` |
| Admin categories | `GET /api/admin/categories`, `POST /api/admin/categories` (admin) | Create `{name,slug,description?}`; no update/delete route | `category/category.route.ts`, `category/category.validation.ts` |

Backend gaps and changes remain **proposed**, not confirmed: expose authenticated technician profile and availability reads; provide a safe customer-visible availability view with booking state; redirect Stripe success/cancel to frontend routes while retaining backend-authoritative webhook processing; support category management edits if required by the finished UI. The backend has no text query, so `app/services/page.tsx` applies the Zod-validated text search to the returned service and technician arrays. `lib/public-api.ts` uses Axios and the server-only `API_BASE_URL` override, defaulting to the deployed API documented in the backend README. `app/technicians/[id]/page.tsx` reads real details, available slots, and reviews. Runtime smoke checks of the built frontend returned live service/profile data, empty search state, and invalid filter messages. Browser-level error UI and form pending behavior remain unverified.
